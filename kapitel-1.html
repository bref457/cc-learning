Was ist Claude Code?

Claude Code ist ein KI-Assistent, der nicht nur redet, sondern selbst anpackt: Er liest dein Projekt, ändert Dateien, führt Befehle aus und prüft, ob alles funktioniert.

Stell dir einen erfahrenen Kollegen vor, der sich an deinen Rechner setzen darf. Du sagst ihm, was du willst, zum Beispiel „Die Anmeldung zeigt nach einem falschen Passwort eine leere Seite, bitte reparieren“. Er sucht die passenden Dateien, liest den Code, macht die Änderung, startet die Tests und sagt dir, was er gemacht hat. Genau das ist Claude Code.

Man nennt so etwas einen Agenten. Ein normaler Chatbot gibt dir nur Text zurück, den du selbst kopieren und ausprobieren musst. Ein Agent erledigt die Schritte selbst.

Die Arbeitsschleife: so denkt und handelt Claude

Jede Aufgabe läuft in einer Schleife aus drei Phasen ab, bis das Ziel erreicht ist. Du kannst jederzeit eingreifen.

Zwei Zutaten: ein Modell, das denkt, und Tools, die handeln

🧠

Das Modell

Das Claude-Modell versteht Code in jeder Sprache, plant die Schritte und entscheidet, was als Nächstes passiert. Es gibt mehrere Modelle: Sonnet reicht für die meisten Aufgaben, Opus denkt bei schwierigen Architekturfragen gründlicher. Wechseln mit /model.

🧰

Die Tools

Ohne Tools könnte Claude nur Text schreiben. Mit Tools kann es Dateien lesen und bearbeiten, Befehle ausführen, im Web suchen und andere Dienste ansprechen.

Claude Code selbst ist die Schicht dazwischen: Es stellt dem Modell die Tools bereit und entscheidet, welchen Kontext das Modell sieht. Diese Schicht nennt man auch Harness (Geschirr, wie beim Pferd).

Tool-ArtWas Claude damit tun kann
📄 Dateienlesen, bearbeiten, neu anlegen, umbenennen, umsortieren
🔎 SucheDateien nach Namen finden, Inhalte durchsuchen, ein Projekt erkunden
▶️ AusführenKommandozeilenbefehle, Server starten, Tests laufen lassen, git
🌐 Webim Internet suchen, Dokumentation abrufen, Fehlermeldungen nachschlagen
🧩 Code-IntelligenzTypfehler sehen, zur Definition springen (braucht ein Plugin)
💡 Tipp

Die eingebauten Tools sind nur die Basis. Mit Skills, MCP, Hooks und Subagenten kannst du Claude später erweitern. Das ist Thema in Kapitel 5 und 6.

Worauf Claude zugreifen kann

Wenn du claude in einem Ordner startest, ist dieser Ordner Claudes Arbeitsplatz.

📁

Dein Projekt

Alle Dateien im Ordner und in Unterordnern. Dateien woanders nur mit deiner Erlaubnis.

🖥️

Dein Terminal

Jeder Befehl, den du selbst ausführen könntest: Build-Tools, git, Paketmanager, Skripte.

🌿

Dein Git-Stand

Aktueller Branch, nicht gespeicherte Änderungen, letzte Commits.

📝

CLAUDE.md

Eine Textdatei mit Regeln und Hinweisen zu deinem Projekt, die Claude bei jedem Start liest.

🧠

Auto-Memory

Notizen, die Claude sich selbst macht, z. B. deine Vorlieben. Werden beim Start geladen.

🔌

Erweiterungen

MCP-Server, Skills, Subagenten und Claude in Chrome, sofern du sie eingerichtet hast.

ℹ️ Warum das wichtig ist

Weil Claude das ganze Projekt sieht, kann es Änderungen über viele Dateien hinweg abstimmen. Ein Assistent, der nur die offene Datei kennt, kann das nicht.

Mehr zu CLAUDE.md und dem Gedächtnis kommt in Kapitel 3.

Installation

Ein einziger Befehl im Terminal genügt. Wähle dein System.

ℹ️ Was du brauchst
  • Ein Terminal (unter Windows: PowerShell oder CMD)
  • Ein Projekt oder einen Ordner zum Arbeiten
  • Ein Claude-Abo (Pro, Max, Ultra, Team oder Enterprise) oder ein Konto in der Claude Console

Du bist in PowerShell, wenn vorne PS C:\ steht.

PowerShell
irm https://claude.ai/install.ps1 | iex

✔ Aktualisiert sich danach automatisch im Hintergrund.

Du bist in CMD, wenn vorne nur C:\ ohne „PS“ steht.

CMD
curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd

✔ Aktualisiert sich danach automatisch im Hintergrund.

PowerShell
winget install Anthropic.ClaudeCode

⚠ Kein automatisches Update. Ab und zu ausführen: winget upgrade Anthropic.ClaudeCode

Bash
curl -fsSL https://claude.ai/install.sh | bash

✔ Aktualisiert sich danach automatisch im Hintergrund.

Bash
brew install --cask claude-code

claude-code ist der stabile Kanal (etwa eine Woche hinter dem neuesten Stand), claude-code@latest bekommt jede neue Version sofort.
⚠ Kein automatisches Update: brew upgrade claude-code

Prüfen, ob es geklappt hat

Der Installer zeigt keinen Fortschritt an, also nicht wundern. Öffne danach ein neues Terminal-Fenster und tippe:

Terminal
claude --version

Wenn eine Versionsnummer mit „(Claude Code)“ erscheint, ist alles bereit.

❌ „claude“ wird nicht gefunden oder nicht erkannt

Der Installationsordner ist noch nicht im PATH, der Liste der Orte, an denen das System nach Programmen sucht. Zuerst ein neues Terminal öffnen. Hilft das nicht, folge der Anleitung PATH reparieren ↗.

❌ „The token '&&' is not a valid statement separator“

Du hast den CMD-Befehl in PowerShell eingegeben. Nimm den PowerShell-Befehl.

❌ „'irm' is not recognized …“

Umgekehrt: Du bist in CMD und hast den PowerShell-Befehl genommen. Nimm den CMD-Befehl.

💡 Tipp für Windows

Installiere zusätzlich Git für Windows. Dann kann Claude die Bash-Shell nutzen, mit der es am besten umgehen kann. Ohne Git nimmt es PowerShell.

🧭 Keine Lust aufs Terminal?

Die Desktop-App (Windows und Mac) enthält Claude Code bereits. Installieren, anmelden, auf den Tab Code klicken, fertig. Oder ganz ohne Installation im Browser unter claude.ai/code. Mehr dazu in Abschnitt 10.

Sicherheitsnetz: Checkpoints und Berechtigungsmodi

Zwei Mechanismen sorgen dafür, dass du die Kontrolle behältst.

⏪

Checkpoints

Bevor Claude eine Datei ändert, merkt es sich den alten Inhalt. Mit Esc Esc spulst du zurück, oder du sagst einfach „mach das rückgängig“.

🚦

Berechtigungen

Legen fest, was Claude ohne Nachfrage tun darf. Wechseln mit Shift+Tab.

⚠️ Achtung

Checkpoints decken nur Dateien ab. Was Claude außerhalb deines Rechners auslöst (Datenbank, E-Mail, Deployment), lässt sich nicht zurückspulen. Dafür sind die Berechtigungen da.

Die Berechtigungsmodi

ModusWann sinnvoll
PlanDu willst erst sehen, wie Claude vorgehen würde, bevor etwas geändert wird.
ManualDu willst jeden Schritt selbst absegnen, z. B. am Anfang zum Lernen.
Accept editsDu vertraust den Dateiänderungen, willst aber bei Befehlen gefragt werden.
AutoStandard in neueren Versionen. Ein Prüfer schaut im Hintergrund jede Aktion an und stoppt die riskanten.

Für Befehle, denen du immer vertraust (z. B. npm test), kannst du eine feste Erlaubnis in den Einstellungen hinterlegen. Das vertiefen wir in Kapitel 4.

Sitzungen und das Kontextfenster

Ein Gespräch mit Claude heißt Sitzung. Jede Sitzung hat ein begrenztes „Arbeitsgedächtnis“: das Kontextfenster.

Sitzungen

  • Claude speichert jedes Gespräch lokal auf deinem Rechner (im Ordner ~/.claude/projects/).
  • Jede neue Sitzung beginnt frisch, ohne das alte Gespräch. Was dauerhaft gelten soll, gehört in die CLAUDE.md.
  • Eine Sitzung gehört zu dem Ordner, in dem du sie gestartet hast.

Das Kontextfenster

Alles, was Claude in einer Sitzung „im Kopf“ hat, liegt im Kontextfenster. Es ist groß, aber nicht unendlich.

  • Wird es voll, fasst Claude das Gespräch automatisch zusammen (Komprimieren). Dabei können frühe Detail-Anweisungen verloren gehen.
  • Mit /compact Fokus auf die API-Änderungen steuerst du, was beim Zusammenfassen erhalten bleibt.
  • Für eine neue, andere Aufgabe lieber /clear: Ein frischer Kontext liefert bessere Ergebnisse.
📌 Merke

Regeln, die immer gelten sollen, gehören in die CLAUDE.md, nicht nur ins Gespräch. Das Gespräch kann beim Komprimieren gekürzt werden, die CLAUDE.md wird jedes Mal neu geladen.

Zwischen den Welten wechseln

Startet eine Aufgabe aus dem Terminal direkt in der Cloud. Danach kannst du sie auf dem Handy weiterverfolgen.

☁️ → 💻 claude --teleport

Holt eine Cloud-Sitzung zurück in dein Terminal.

Macht deine laufende Sitzung im Browser und auf dem Handy erreichbar.

⌨️ → 🖼️ /desktop

Übergibt die Terminal-Sitzung an die Desktop-App, wo du Änderungen visuell prüfst.

ℹ️ Gut zu wissen

  • Sie zählen zu den normalen Nutzungslimits deines Plans. Für den Cloud-Server zahlst du nichts extra.
  • In der Cloud hat Claude nicht deine lokale Einrichtung (lokale Skills, Einstellungen). Die CLAUDE.md im Repo liest es aber schon.

Projekte, Mods & Erweiterungen im Überblick

Ein erster Blick auf Funktionen, die über eine einzelne Sitzung hinausgehen. Jede bekommt später ihr eigenes Kapitel.

🗂️ Projekte

Ein Projekt ist ein langes Gespräch, in dem Claude als Koordinator arbeitet. Du wirfst Aufgaben hinein, und Claude startet für jede einen eigenen Thread: eine eigene Cloud-Sitzung, die parallel arbeitet und danach Bericht erstattet.

  • Kontext einmal festlegen: Anweisungen und Gedächtnis des Projekts gelten für jeden neuen Thread.
  • Weggehen und zurückkommen: In der Übersicht siehst du, was fertig ist und was auf deine Antwort wartet.
  • Nicht nur Code: Du kannst auch Dokumente hochladen und dazu Fragen stellen.
  • Projekte sind im Moment eine Beta für Pro, Max und Ultra und kommen nach und nach bei allen an.
🧭 Beispiel

Genau so entsteht dieses Lernwiki: In einem Projekt „CC_Learning“ bekommt jedes Kapitel seinen eigenen Thread.

📖 Original: Projekte ↗

🎨 Mods

Ein Mod verändert, wie Claude Code selbst aussieht und sich verhält. Er ist ein kleines Plugin in JavaScript oder TypeScript, das innerhalb von Claude Code läuft. Damit kann er zum Beispiel:

  • eigene Bereiche mit Knöpfen und Feldern in die Oberfläche zeichnen (etwa eine Anzeige, wie voll der Kontext ist),
  • einen riskanten Befehl wie rm -rf anhalten und nachfragen,
  • eigene /befehle hinzufügen, die sofort laufen.

Du musst Mods nicht selbst programmieren: Beschreib Claude, was du willst, und es schreibt den Mod für dich. Mods laufen in der CLI, der Desktop-App und VS Code.

⚠️ Achtung

Ein Mod läuft mit deinen Rechten: Er kann deine Dateien lesen, Programme starten und deine Sitzung sehen. Installiere nur Mods von Quellen, denen du vertraust.

Tipps für den Start

Fünf Gewohnheiten, die von Anfang an bessere Ergebnisse bringen.

1. Sei konkret

❌ Unklar„Behebe den Fehler.“
✅ Konkret„Behebe den Login-Fehler: Nach einem falschen Passwort sehen Nutzer eine leere Seite.“

2. Große Aufgaben in Schritte teilen

Prompt
1. Leg eine Datenbanktabelle für Benutzerprofile an.
2. Bau eine Schnittstelle, um Profile zu lesen und zu ändern.
3. Erstell eine Seite, auf der Nutzer ihr Profil bearbeiten können.

3. Erst erkunden lassen, dann ändern

„Analysiere zuerst das Datenbankschema und erklär es mir“ ist ein guter Start, bevor du etwas umbauen lässt. Der Plan-Modus ist genau dafür da.

4. Delegieren statt diktieren

Gib Ziel und Hintergrund, nicht jeden Handgriff. Welche Dateien es lesen muss, findet Claude selbst heraus.

Prompt
Der Bezahlvorgang klappt nicht bei abgelaufenen Karten.
Der Code liegt in src/payments/. Kannst du das untersuchen und beheben?

5. Im Gespräch korrigieren

Der erste Versuch ist nicht perfekt? Kein Neustart nötig, sag einfach: „Nicht ganz, das Problem liegt in der Sitzungsverwaltung.“ Wenn Claude nach zwei Korrekturen immer noch danebenliegt, ist ein frischer Start mit /clear und einem besseren Prompt meist schneller.

💡 Claude kann dir Claude Code erklären

Frag direkt in der Sitzung: „Wie richte ich Hooks ein?“ oder „Wie sollte ich meine CLAUDE.md aufbauen?“. Und /doctor findet Probleme in deiner Einrichtung.

Häufige Fragen

Kostet Claude Code etwas?

Ja. Du brauchst ein Claude-Abo (Pro, Max, Ultra, Team oder Enterprise) oder ein Console-Konto, bei dem du pro Nutzung zahlst. Die Nutzung zählt zu den Limits deines Plans, auch Cloud-Sitzungen.

Kann ich auf Deutsch mit Claude reden?

Ja, ganz normal. Claude antwortet dann auch auf Deutsch.

Brauche ich Programmierkenntnisse?

Für den Einstieg nicht unbedingt. Du solltest aber verstehen, was Claude ändert, bevor du es übernimmst. Der Plan-Modus und das Nachfragen („Erklär mir, was du geändert hast“) helfen dabei.

Kann Claude etwas kaputt machen?

Dateiänderungen kannst du mit Esc Esc zurückspulen. Bei Aktionen nach außen (Datenbanken, Deployments) schützen dich die Berechtigungsmodi. Nutze außerdem git, dann ist jeder Stand sicher.

Wo ist der Unterschied zwischen Claude im Chat und Claude Code?

Der Chat auf claude.ai beantwortet Fragen. Claude Code arbeitet direkt in deinem Projekt: Es liest und ändert Dateien und führt Befehle aus.

Was ist der Unterschied zwischen Desktop-App und Terminal?

Dieselbe Maschine, andere Bedienung. Das Terminal kann am meisten (z. B. Skripte), die Desktop-App ist grafisch und zeigt Änderungen übersichtlich an.
